# Milk World — API Documentation

## 1. Общая информация

Backend: Node.js, Express, TypeScript, Supabase.

Базовый URL для локального запуска:

`http://localhost:3000/api`

Все ответы API возвращаются в формате JSON, если не указано иное.

## 2. Авторизация

Для защищённых запросов используется Bearer Token.

Заголовок:

`Authorization: Bearer YOUR_ACCESS_TOKEN`

Роли:
- `admin` — полный доступ к административным операциям.
- `editor` — создание и редактирование товаров и категорий.
- Неавторизованные пользователи — доступ только к публичным операциям.

## 3. Управление товарами

### 3.1 Получить список товаров

**GET** `/products`

Авторизация: не требуется.

Успешный ответ: `200 OK`.

### 3.2 Получить товар по ID

**GET** `/products/:id`

Пример:

`GET /products/258`

Авторизация: не требуется.

Возможные ответы:
- `200 OK` — товар найден.
- `400 Bad Request` — некорректный ID.
- `404 Not Found` — товар не найден.

### 3.3 Создать товар

**POST** `/products`

Авторизация: `admin`, `editor`.

Пример тела запроса:

```json
{
  "name": "Новое молоко",
  "description": "Молоко 3.2%",
  "image_url": "https://example.com/milk.jpg",
  "category": "Молоко",
  "is_active": true
}
```

Успешный ответ: `201 Created`.

Возможные ошибки:
- `400 Bad Request` — некорректные данные.
- `409 Conflict` — товар с таким названием уже существует.

### 3.4 Обновить товар

**PATCH** `/products/:id`

Авторизация: `admin`, `editor`.

Пример:

`PATCH /products/258`

Тело запроса содержит поля товара, которые необходимо обновить.

Успешный ответ: `200 OK`.

Возможные ошибки:
- `400 Bad Request` — некорректный ID или данные.
- `404 Not Found` — товар не найден.

### 3.5 Удалить товар

**DELETE** `/products/:id`

Авторизация: только `admin`.

Успешный ответ: `200 OK`.

Возможные ошибки:
- `400 Bad Request` — некорректный ID.
- `404 Not Found` — товар не найден.

## 4. Поиск товаров

### 4.1 Поиск

**GET** `/products/search`

Авторизация: не требуется.

Поддерживается поиск товаров по предусмотренным параметрам: названию, категории и содержанию жира, а также сортировка и пагинация.

Точные названия query-параметров необходимо сверить с реализацией `productSearchService.ts`.

## 5. Управление категориями

Базовый путь: `/products/categories`.

### 5.1 Получить список категорий

**GET** `/products/categories`

Авторизация: не требуется.

Успешный ответ: `200 OK`.

Пример:

```json
{
  "success": true,
  "data": [
    "Молоко",
    "Кисломолочная продукция",
    "Сметана",
    "Творог",
    "Йогурты",
    "Сыры",
    "Масло",
    "Мороженое",
    "Сливки",
    "Десертная продукция",
    "Сухие молочные продукты"
  ]
}
```

### 5.2 Создать категорию

**POST** `/products/categories`

Авторизация: `admin`, `editor`.

Тело запроса:

```json
{
  "name": "Биопродукты"
}
```

Успешный ответ: `201 Created`.

Возможные ошибки:
- `400 Bad Request` — название не указано или пустое.
- `409 Conflict` — категория уже существует.

### 5.3 Переименовать категорию

**PATCH** `/products/categories/:id`

Авторизация: `admin`, `editor`.

Пример:

`PATCH /products/categories/23`

Тело запроса:

```json
{
  "name": "Биопродукты"
}
```

Успешный ответ: `200 OK`.

При переименовании обновляется название категории у связанных товаров.

Возможные ошибки:
- `400 Bad Request` — некорректный ID или название.
- `409 Conflict` — категория с таким названием уже существует.

### 5.4 Удалить категорию

**DELETE** `/products/categories/:id`

Авторизация: только `admin`.

Пример:

`DELETE /products/categories/23`

Успешный ответ:

```json
{
  "success": true,
  "message": "Категория успешно удалена"
}
```

Возможные ошибки:
- `400 Bad Request` — некорректный ID.
- `404 Not Found` — категория не найдена.
- `409 Conflict` — категория используется товарами и не может быть удалена.

## 6. Системные маршруты

Системные маршруты подключены через `/api` и определены в `systemRoutes.ts`.

Точные URL и ответы необходимо дополнить по фактической реализации.

## 7. Авторизация пользователей

Маршруты авторизации подключены через `/api/auth`.

### Вход

**POST** `/auth/login`

Тело запроса и формат ответа необходимо сверить с `authController.ts`.

Успешный вход возвращает данные пользователя, access token и refresh token.

## 8. Права доступа

| Операция | Метод | admin | editor |
|---|---|---|---|
| Просмотр товаров | GET | Да | Да |
| Создание товара | POST | Да | Да |
| Редактирование товара | PATCH | Да | Да |
| Удаление товара | DELETE | Да | Нет |
| Просмотр категорий | GET | Да | Да |
| Создание категории | POST | Да | Да |
| Переименование категории | PATCH | Да | Да |
| Удаление категории | DELETE | Да | Нет |

## 9. База данных

Основные используемые таблицы Supabase:
- `products` — товары;
- `categories` — категории;
- `translations` — переводы;
- `feedback` — обратная связь.

## 10. Примечание

Документация описывает реализованные и проверенные операции управления товарами и категориями. Маршруты поиска, авторизации и системные маршруты требуют дополнительной сверки с исходным кодом перед финальной публикацией документации.
