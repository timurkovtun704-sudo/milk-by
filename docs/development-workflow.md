# Процесс разработки

## Ветки

- `main` — стабильная версия.
- `develop` — интеграционная ветка.
- `feature/<area>-<task>` — отдельная задача, например `feature/frontend-catalog`.

## Порядок работы

1. Получить актуальный `develop`: `git pull origin develop`.
2. Создать feature-ветку.
3. Реализовать задачу и проверить локально.
4. Отправить ветку на GitHub.
5. Создать Pull Request в `develop`.
6. После проверки тимлид принимает изменения.

Не добавлять секреты и реальные `.env` в репозиторий.
